# Web 执行受阻后的自动分析

会话接入失败、认证无法确认、导航循环或同一步首次失败且重新观察仍无法继续时，自动进入一次有界诊断；保留原始业务检查 failed/blocked，不以静态分析完成改成 passed。不重复点击、重新提交或循环换浏览器。Windows 企业 SSO 现场复测交给用户。

## 按可用证据分流

1. 记录原动作、预期、实际现象、当前会话绑定及工具错误类别。连接/启动/权限错误先走 web-session.md 的对应诊断。
2. 目标身份已确认、工具仍允许读取当前页面时，在同一会话分析已加载 HTML 结构、脚本/CSS 引用、iframe、跳转标记与已有错误证据。SSO origin 不在获准范围时只记跨域跳转，不能自动扩展分析范围。
3. ego-lite 可调用 `scripts/ego_session.mjs` 的 `collectStaticSignals(page, allowedOrigins)`：allowedOrigins 来自已确认范围，函数不发请求，只返回固定结构计数与限制。若需进一步定位，沿用当前宿主工具读取范围内已交付资源，按 web-app-reverse 的资源账本记录已分析、缺失和仅引用资源；不默认递归下载全部 bundle。
4. 页面无法连接、URL 未确认或遇到权限门禁时，仅分析已持有的脱敏 HTML/JS/CSS、HAR/trace 或错误输出；缺少材料就列出用户需提供的最小材料。不得通过 fetch、另一工具或新浏览器绕过当前阻断。

当前已交付文件的静态分析可复用 `web-app-reverse/scripts/inspect_assets.py`（读取该 skill 的入口及 inspection.md）。按资源账本分析本次失败相关的文件；需要补充的资源和运行验证列入下一步。

## 诊断报告

输出：原测试状态、已确认事实（附脱敏证据定位）、原因假设、证据缺口、最小下一步及用户复测步骤。区分：

- 连接/环境：进程、CDP、页面文件、权限或 URL 身份问题。
- 认证：登录 UI、业务已登录标记缺失、回调/跳转记录；只凭密码框不能确认会话过期。
- 页面资源：已观察的脚本错误、缺失 chunk、资源加载失败、静态路由或配置冲突。
- 防自动化候选：明确的 challenge 页面/验证码、WAF 响应或工具返回的拒绝证据。403/429、登录循环或静态 bundle 中出现相关字符串都不能单独证明企业 SSO 防爬虫；没有现场证据时保持假设。

静态页面无法单独确认 Cookie 是否写入、SameSite 是否拦截、企业设备信任是否缺失或 SSO 服务端风控原因。仅在已有脱敏日志支持时写为事实；否则建议用户在原会话复测并提供对应错误类别。不要修改浏览器指纹、自动解验证码、注入 Token 或关闭企业防护。

原始资源可能包含内联凭证和个人信息。默认不导出完整 HTML、正文、表单值、URL 查询参数、Cookie/storage/认证头；额外产物在本地受控目录保存前先脱敏。
