# Web 执行

## 工具路线与准备

用户指定工具优先；默认由 vercel-labs/agent-browser 负责探索、Midscene 负责重复回归。先检查已安装版本、`agent-browser --help` 和本次所需子命令帮助，再使用 open → snapshot → 交互 → 新 snapshot / screenshot 的循环。不能凭教程猜参数、复用页面变化前的 ref，或擅自启动远程调试/连接无关会话。工具不可用时报告具体缺口，不自动全局安装。

上述路线不可用或无法完成目标交互时，回退到当前宿主的 Computer Use 技能/工具：存在对应技能就先读其入口，否则使用已暴露工具的文档，不虚构技能或 API。按工具规则选择目标应用/浏览器，观察最新截图或可访问性树后操作，每次状态变化重新观察。若工具被权限或安全门禁阻止，不得换路线绕过限制。Computer Use 可以完成实际交互和视觉复核，但不冒充已生成/运行 Midscene 回归，也不凭屏幕操作声称 Network、DOM、持久化或精确对比度已验证；缺失的 oracle 单独记录。三条路线都无法执行才将依赖步骤记为 blocked。

探索与重复回归分开：agent-browser 用于真实用户操作与截图；已有 Midscene 项目沿用其 AI fixture 做语义操作和视觉断言；Playwright/DOM/Network/axe-core 提供精确判断。DevTools 用于定位原因，不以源码推理代替操作。API 必须对照目标项目当前依赖和类型声明；不把教程版本、缓存或报告平台整体搬入业务仓库。

记录目标 build、URL 的脱敏标识、浏览器版本、viewport、主题、语言、角色、初始数据和工具版本；使用模型时另记模型配置与版本（不含密钥）。视口从需求选择，390px 等教程值只是示例，不自动扩大兼容范围。

先发现当前宿主可用的浏览器控制能力，读取其文档，再使用其允许的 DOM/可访问性树、截图和语义定位操作。每次改变页面状态后重新观察，避免旧节点定位。沿用用户指定浏览器、标签页和会话，不读取无关标签页。

范围内覆盖正常/异常输入、键盘与焦点、页面跳转、刷新/返回、登录过期、角色权限、状态恢复和必要视口。只有列入范围的浏览器/视口才算已测兼容组合。弱网、离线、模拟时间等须工具实际支持且适合目标；模拟器结果不标为物理设备结果。

副作用明确到动作：提交订单、付款、发消息、删数据等遵守当前授权。观察 Network 与重放请求是不同操作。仅记录脱敏业务关联标识，避免导出认证头。没有代码仓库、需要逆向 DOM/JS bundle 和浏览器证据以建立测试全局视野时使用 web-app-reverse；先经 TestSpec 形成并确认用例，再进入本 skill 执行。

对每步记录 action、预期 oracle、actual、status 和证据。页面提示与后端最终状态分别断言；需求允许时用重新查询、列表刷新或另一终端观察作为黑盒 oracle，无须强制查询数据库。

## 风险驱动探索

先完成关键用户任务，再针对当前页面构造边界：空/超长/重复输入、末行菜单、空列表、窄屏、真实主题、失败请求与状态恢复。条件需要数据修改或故障注入时只用已授权测试环境；只读范围不能为凑覆盖创建业务数据。每项发现记录可观察现象、最小触发条件和用户影响，不只写“布局异常”。

| 风险 | 动作与判断依据 | 易产生假绿的信号 |
| --- | --- | --- |
| 浮层遮挡 | 打开面板，截图复核关键字段；几何和命中测试辅助验证 | DOM 存在、z-index 数字大 |
| 菜单裁切 | 在末行/容器边缘打开，查看末项完整性与可达性；有副作用的菜单项只在授权范围点击 | 菜单容器 visible |
| 长文本/窄屏 | 用边界数据和指定视口，验证关键列/按钮仍在可见区域且可操作 | 页面整体没有报错 |
| 暗色对比度 | 切换主题后用规则扫描/颜色计算验证约定阈值，截图补整体可读性；报告未能计算项 | AI 说“看起来清楚”、零违规却有 incomplete |
| 空表单 | 错误说明、弹窗状态，加独立的创建请求/列表或持久化结果；监听先于动作 | 只看没有成功 toast（toast 自己可能已坏） |
| 瞬时反馈 | 动作前布置有界连续观察，覆盖约定时间窗，见下节 | 动作完成后的单张截图 |

几何在视口内不证明未被祖先裁切；中心点命中不证明边缘完整；截图语义不证明数值阈值和持久化。按目标组合互补信号，不能把单个辅助 probe 当最终业务断言。

## 瞬时状态取证

先明确要求是“至少出现一次”还是“在指定时段持续可见”，以及时长/允许间隙。开始录像或安装目标限定的观察器 → 确认就绪 → 触发动作 → 等待业务信号并覆盖约定窗口 → 在 finally 中停止并收集 → 断言。没有捕获到目标意味着缺证据，不是通过。

允许 DOM 求值时可组合 MutationObserver 和有界帧采样：记录相对时间、目标是否存在、宽高及四边是否在视口内、计算样式、关键点命中；不收集整页文本或表单值。MutationObserver 单独不能覆盖 CSS 动画、滚动和遮罩变化；轮询也会漏掉采样间隙，因此记录采样频率、丢帧和遮挡检查的局限。发生导航/异常仍需清理 observer、定时器及本次创建的录制。

教程中 `some(inViewport && topmost)` 仅证明某个采样点满足条件。持续性要求必须检查整个指定窗口的样本与缺口，并保留视频/序列供复核；不把离散采样描述成数学意义的全程证明。

## 修复复测与回归交接

修复后重跑相同角色、数据、视口、主题和动作，保留修复前后证据；复测组织交给 defect-verification。新回归进入门禁前，优先在隔离缺陷版本或可恢复的合成失败夹具上证明 RED，再在修复版本上证明 GREEN。不得回滚用户工作树；无法获得缺陷版本时标记“检测有效性未验证”，不能仅凭跑绿称为可信回归。

用户要求生成回归时，沿用目标仓库既有技术栈；有 Midscene 时用语义操作/视觉断言，硬规则仍用确定性 oracle。新增脚本应携带 case ID、风险、最小前置数据、环境、动作、独立断言、证据、清理和 RED/GREEN 结果。模型定位缓存可复用，但最终断言重新执行；首轮失败和后续重试分别保留，不能重试洗绿。

分级沿用项目 strategy：P0 核心可用性/关键业务，P1 高频与重要边界，P2 扩展环境与探索（只是默认示例，暗色等也可能是核心风险）。门禁明确触发条件、选择的用例、失败阻断与耗时预算；零用例、环境缺失和命令失败不算通过。只有用户授权接入门禁时才改 CI/Husky，不因执行测试自动安装平台或修改 Git hooks。同一内容已有有效验证结果可复用，不重复跑昂贵模型检查。
